Portfolio architecture

Static Astro 7 site, TypeScript strict, plain CSS, no UI framework, no server. Built from the working tree (not HEAD), verified against source files.

Two inputs

src/config/site.ts (identity, section order, contact, analytics) and six Zod content collections.

Build-time only

Pages call getCollection in frontmatter and emit plain HTML plus 4 text/XML endpoints into dist/.

Hard gates

npm run build = astro check && astro build. Type or schema errors fail CI and block deploy.

Deploy

GitHub Actions to GitHub Pages at diallofrancispatrick.com.

System architecture

Components read site and collections directly; pages fill BaseLayout slots (header, default, footer). No client:* islands; interactivity is vanilla TS in <script> blocks.

Component composition

BaseLayout (title, description, ogImage?, jsonLd?, noindex?)
 +- slot header  -> Header      (sticky nav, details toggle, theme/accent menu, CV link)
 +- main > slot  -> page content
 |    on "/":  hero (inline) then for each visible site.sections[]:
 |             componentMap[id] -> About | Skills | Experience | Projects
 |                                 | Education | BlogPreview | Contact
 +- slot footer  -> Footer      (build date, /blog/, /cv/, back-to-top)

All components are prop-less and self-fetching. Only index.astro queries a collection itself (skills, for Person JSON-LD). Section data sources: Skills (skills), Experience (experience, render()), Projects (projects, category chips), Education (education + certifications), BlogPreview (blog, latest 3), About (profile image via import.meta.glob), Contact (site.contact, socials).

Data flow

Slugs come from the file name (entry.id). Blog pages add readingTime, similarPosts (Jaccard on tags) and BlogPosting/Breadcrumb JSON-LD. Drafts: shown in dev, hidden in prod on blog pages and preview; RSS, 404 and llms endpoints always hide them.

Content schemas

Enums: tint = crimson | cobalt | emerald | amber; skill level = daily | comfortable | learning; months match ^\d{4}-\d{2}.

Styling and design tokens

One global src/styles/tokens.css (about 270 lines) imported in BaseLayout; components use scoped <style> and must not hardcode colour, size or spacing.

  • Light: --bg #f4f6f9, --ink #132033; tints crimson #c8102e, cobalt #1d4ed8, emerald #047857, amber #a34d06; --accent defaults to cobalt.
  • Dark: :root[data-mode='dark'] plus prefers-color-scheme when no explicit mode. The values are duplicated in both blocks.
  • Accent: :root[data-accent=...]. Per-item colour: data-tint exposes --tint.
  • Type scale ratio 1.25 (--text-sm 0.8rem to --text-3xl 3.052rem); spacing --space-1..6; --measure: 66ch.
  • public/theme-init.js sets data-mode, data-accent, data-details from localStorage before paint.
  • Also: print rules, reduced-motion switch, @view-transition { navigation: auto }.

CI/CD

.github/workflows/deploy.yml runs on push to main, pull requests and manual dispatch (Node 22, ubuntu-latest): npm ci, npm run build, npm test. Upload of ./dist and deploy-pages@v4 run only for pushes to main; PRs build and test only. Concurrency group pages cancels in-progress runs. No lint, e2e or Lighthouse job.

How-to recipes

New blog post

Create src/content/blog/<slug>.mdx (not .md) with title, summary (max 160), date, tags. Static images in public/images/, covers relative to the file.

New project

src/content/projects/<slug>.md; plain max 220; start as YYYY-MM. New category becomes a filter chip.

New job

src/content/experience/<slug>.md; end: null if current; max 4 highlights.

Skills / education / certs

Append an item with a unique id to the YAML file.

Site-wide change

Edit site.ts: toggle or reorder sections, Formspree id, socials, analytics, CV file.

New homepage section

Create SectionX.astro, add to componentMap in index.astro, add entry to site.sections.

New third-party origin

Add it to the CSP directives in astro.config.mjs or the browser blocks it.

Change domain

Update site.url, astro.config.mjs site, and both CNAME files.

Run

astro dev --background (see astro dev stop|status|logs), npm run build, npm test.

Gotchas and known issues

  • Domain in three places: site.url, astro.config.mjs site, public/CNAME must be synced by hand (root CNAME is redundant).
  • Header links are bare hashes (href="#about"), so on blog, cv and project pages they do not reach home sections. Verified in source; not browser-tested.
  • Dead knobs: featured (schema and content set it, nothing reads it), site.defaults, links, clientLogos, cv.updated have no consumer; analytics goatcounter is typed but not implemented.
  • Draft handling is uneven between blog pages and RSS/404/llms endpoints (harmless in production).
  • Image fields use image(): old string paths fail the build; paths are relative to the content file.
  • CSP blocks external images, scripts and fonts until whitelisted; inline scripts without a hash are blocked, hence theme-init.js in public/.
  • Dark palette duplicated in two CSS blocks; also duplicate h1, h2, a, html rules in tokens.css.
  • Placeholder assets: og-default.svg shows placeholder identity (SVG OG images are poorly supported by social crawlers); seed content (Northwind Labs, DataLoom, Globex Bank) mixed with real CV history; placeholder repo URL in pipeline-canary.md.
